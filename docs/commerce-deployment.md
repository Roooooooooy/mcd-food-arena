# 本机账号版运行

麦麦二选一的真实账号功能在用户自己的电脑上运行：网页负责挑选和确认，本机 Node 服务调用官方 MCP，读取本人优惠券、核价和创建用户已确认的待支付订单。支付在返回的官方页面完成。无需云端托管，也不需要注册 Render。GitHub Pages 继续提供免 Token 的门店快照试玩。

## 启动

使用 Node 24（本次验证 24.21.0）：

```bash
npm --userconfig=/dev/null ci --include=dev
npm --userconfig=/dev/null run build:commerce
npm --userconfig=/dev/null start
```

打开 `http://127.0.0.1:8788`。在页头展开“连接账号”，粘贴从[麦当劳官方](https://open.mcd.cn/mcp)取得的本人 Token。连接后自动读取所选门店真实菜单与本人券包，也可以先试玩已保存的门店快照。

这一个本机进程提供网页、图片、`/api/commerce/*` 和 `/healthz`，默认只监听 `127.0.0.1`。服务不会自动读取 `.env.local` 或自动连接账号。每位使用者在自己的电脑上启动服务、使用自己的 Token。

构建需要开发依赖，所以安装时保留 `--include=dev`。默认端口被占用时，可运行 `PORT=8989 npm --userconfig=/dev/null start`，再打开 `http://127.0.0.1:8989`；程序不会自行选择其他端口。原有 `dev:api` 的 8787 只读接口仍兼容旧脚本。

## 使用

1. 连接自己的 Token，选择门店和餐品分类。
2. 二选一卡下查看相关券，整张卡面选择餐品；当前菜单未返回的餐品灰显并禁选。
3. 在最终餐单调整规格、数量和定制。查看券方案的匹配餐品、额外餐品和官方价差，按需替换或撤销。
4. 获取当前餐单官方报价，核对门店、金额和取餐方式。
5. 用户明确点击创建订单后，再前往官方支付页面。查询结果未确认时，先到官方 App 核对订单，避免重复下单。

Token 输入提交后立即清空，不写浏览器存储，仅在本机服务的内存会话中使用。默认连接有效期 30 分钟；断开、过期或退出服务后需要重新连接。关闭终端中的服务可按 Ctrl+C。订单不会因为退出本机服务而自动取消，请到官方渠道查看。

本人挑选进度、券包、报价和订单提交状态只保留在本次连接中，服务重启后不会恢复。Token 不放入任何 `VITE_*` 构建变量，也不写进公开仓库或餐单导出。

## 当前交付范围

当前交付为本机真实账号功能加公网快照试玩，不安排云端注册、GitHub 托管授权或公网个人账号服务。已有 `render.yaml` 和服务端 HTTPS 配置是此前可部署方案的兼容文件，本机运行不使用它们。参赛材料仍需按官方要求提交公开源码、MCP 接入说明和脱敏配置；正式报名另按用户指令处理。
